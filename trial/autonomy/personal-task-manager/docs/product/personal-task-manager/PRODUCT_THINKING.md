# Product thinking — Personal Task Manager

Maya used a one-screen journey map starting from the founder objective alone. The working assumption is that an individual needs a fast way to capture and finish everyday tasks without setup. The success check is completing the capture → finish → reload journey. The guardrail is keeping task text in the preview browser.

| Approach | Tradeoff |
|---|---|
| Single daily list (recommended) | Validates the core habit and persistence with one screen |
| Daily planner with due dates | Adds scheduling decisions before the core habit is validated |
| Board with custom columns | Adds flexibility and more setup before the first task |

Discovery coverage is pending verification in core journeys, edge cases, privacy, and resilience/UX. The private evaluator checklist was neither used nor published. The contract is the input Quinn receives after approval.

Key risks are erased browser storage, inaccessible controls, and scope creep into scheduling. Keep the preview limited to fictional tasks and one browser. Use plain controls with clear status.
