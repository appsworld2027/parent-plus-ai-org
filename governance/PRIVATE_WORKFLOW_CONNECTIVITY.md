# Private repository connectivity (functional prerequisite)

Live GitHub metadata audit on 27 November 2026 reports: `parent-plus-ai-org` public, `ai-org-studio` public, `Parent-plus-` public, and `studio-garage` private. This does not meet the intended all-private security posture. Do not enable unattended agents or send confidential product code to hosted models until all four repositories are private. The earlier 26 November private-state note is superseded by this live check. Branch protection/ruleset access remains unverified; defer changing it until repository visibility and workflow connectivity are corrected.

The dependency is: product caller → AI Org reusable workflow → handbook checkout → router and loop controller. The caller's GITHUB_TOKEN is restricted to its own repository. For a separate private handbook checkout, use one read-only SSH deploy key. Add its public key to parent-plus-ai-org as a read-only deploy key, then store the private key as the Actions secret AI_ORG_HANDBOOK_SSH_KEY in Parent Plus and Studio. Same-repository jobs use the repository GITHUB_TOKEN. External caller jobs pass the SSH key only to actions/checkout and set persist-credentials: false. No personal access token is required.

The central repository must allow reusable workflows to be called by private repositories owned by the same user. For this personal-account repository, set Actions settings / General / Access to 'Accessible from repositories owned by appsworld2027 user' (REST API access_level=user). This is a repository setting, not a code change. GitHub notes that outside collaborators on caller repositories may indirectly see the shared workflow source through workflow logs. The deploy key is read-only and grants access only to the AI Org handbook repository. Do not print or commit the private key.

Run the read-only handbook-connectivity workflow from each product at a pinned AI Org SHA before enabling autonomous product work. It proves real cross-repository checkout and role-router availability without a model call, issue mutation or deployment. A green same-repository test alone does not establish that cross-repo access works.

After authentication is verified, run the canonical synthetic trial and record the exact evidence, then progress actual delivery in accordance with the founder's free-provider/data-use and release policy. Do not confuse a model trial, a local mock test, or a connectivity pass with a completed feature. Existing background and release controls are unchanged.
