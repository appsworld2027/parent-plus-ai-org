## Candidate interface

Iris produces exactly **board.html** and **walkthrough.md** via the frozen casebook manifest. HTML must be self-contained (inline CSS/JS, no external dependencies, requests or navigation), keyboard-accessible at 320px and desktop. The trusted controller injects these asynchronous synthetic service functions before loading the HTML:

- `window.boardList()`: returns `{state:"ok"|"offline"|"error"|"denied",records:[{id,title,version}]}`. Offline includes cached read-only records; error/denied never leaks other tenants.
- `window.boardSave({id,title,expectedVersion})`: exact fields, create id null/version 0, edit existing ID/exact observed version; trimmed title 1–80. Returns `{state:"ok",record:{id,title,version}}` or `{state:"stale",record?}` or state denied/error/offline/invalid. Do not show success or modify the list before confirmation. No real network, no duplicate save, no auto-retry after uncertain/stale response.

Use accessible names and roles so independent tests can interact like a user: heading Reminder board, textbox Reminder title, submit button Save reminder, list named Reminders, per-item button Edit reminder plus the full title. Empty message No reminders. Visible live status starts Loading, Saving, Saved or Offline as applicable; failure feedback is a visible role=alert with plain-language explanation. Keep the draft on stale/denied; explicit Refresh reminders reloads latest versions without losing the draft; user chooses to retry. Initial load failure exposes Retry loading. Offline shows cached reminders and disables save. Title invalid shows accessible error without write; optional maxlength=80 must have visible 1–80 guidance. At 320px no horizontal scrolling/clipped status or controls, and long title wraps. Keyboard Tab/Enter can complete the save. Use proper labels, focus indicators, readable contrast and tap targets. Walkthrough maps states and acceptance behaviors and labels unobserved test/review evidence pending.

## Evidence and security boundary

The trusted controller builds a local immutable image from Playwright v1.64.1, pinned registry manifest digest, exact package lock and its own runner. Candidate markup is the only mounted file; no repository, credentials, writable host mount, privileged Docker socket or network is exposed. Non-root user; Docker read-only, dropped capabilities, no-new-privileges, CPU/memory/PID/time limits; Chromium sandbox requested in addition to the Docker isolation using the version-pinned official Playwright seccomp profile. A browser sandbox launch or incomplete runner failure is infrastructure failure, never a pass. Treat untrusted model HTML as code; do not run it in an authenticated human browser. No use of browser preview or production access is granted.

Ten locked real browser checks cover loading/empty, delayed save confirmation, exact edit version, invalid input, stale recovery, denied save, offline, retry, 320px keyboard/overflow and absence of external requests. Node-side mock service is isolated from candidate DOM; receipt validation requires all exact check IDs, sandbox flag, and compatible process exit.
